# AMO reviewer notes

## Build and package boundary

The submitted Firefox package is generated by `npm ci && npm run build:firefox`. The build concatenates the
human-readable modules in `src/modules` into `dist/firefox/Dollchan_Next.js`; it does not minify or obfuscate them.
`npm run verify` runs unit and release-contract tests, the matcher benchmark, ESLint, a clean-tree build check and
Mozilla's add-ons linter.

The extension contains no userscript release, remote executable code, telemetry, analytics or update checker.

## Network boundary

Normal page updates, posting and media loads communicate with the imageboard selected by the user. Optional
YouTube/Vimeo metadata and image-search integrations are disabled by default. `readCfg()` in `Storage.js` forces
`YTubeTitles`, `imgSrcBtns`, `addVimeo` and `addVocaroo` off until the user enables the named providers in the
Privacy settings page. Image-search uploads additionally require a direct click on the selected media control.

## Dynamic markup review

The add-ons linter currently reports a bounded set of `UNSAFE_VAR_ASSIGNMENT` warnings in the assembled content
script. The warning budget is enforced by `scripts/check-web-ext-lint.mjs`, so a new warning fails CI.

The shared `$bBegin`, `$aBegin`, `$bEnd` and `$aEnd` helpers insert extension-owned templates into the imageboard
DOM. Other flagged sites fall into these reviewed groups:

- extension-owned SVG, controls and localized strings;
- numeric post, thread and video identifiers constrained by board parsers;
- same-board HTML parsed in an inert `createHTMLDocument` before selected nodes are adopted back into that board;
- existing DOM fragments moved within the same imageboard document.

No popup, options or background-page code assigns imported JSON, provider responses or free-form external strings
to an HTML sink. Those surfaces use `textContent`, form values and DOM properties. Provider metadata displayed by
the content script is also assigned as text. The remaining warnings are therefore content-script template/parser
boundaries rather than privileged extension-page HTML injection.

## Reproduction

See `BUILD.md`. Node.js 22 and the dependencies locked in `package-lock.json` are sufficient.
